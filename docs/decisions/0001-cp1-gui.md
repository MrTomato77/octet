# ADR 0001: egui/eframe for the CP1 prototype

Date: 2026-10-17

Status: selected for the prototype, subject to remaining Windows input/accessibility checks.

## Decision

Use egui/eframe 0.37.0 with the Glow renderer, system fonts, clipboard integration and AccessKit. Pin Rust 1.98.0 and commit the dependency lockfile when the project is committed later. This task creates no Git commit.

## Evidence

The Windows MSVC build completed on this host. The current egui text pipeline includes shaping; rendered Thai fixture names and notes use installed Segoe UI/Leelawadee UI. In-process UI tests confirm Thai text insertion, search focus and explicit preview keyboard behavior. App framebuffer captures inspect the actual native renderer, including compact and Thai layouts.

The first candidate met the available rendering/layout checks, so no second iced implementation was needed. This is not a comparative benchmark. AccessKit exposes the window and controls, but that alone does not establish screen-reader usability.

## Remaining checks

Windows interaction automation could inspect the accessibility tree but activation/input failed with `GetCursorPos failed: Access is denied (0x80070005)`. Windows screenshots from that desktop were black. Own-app framebuffer captures and headless input tests were used for their respective scopes, not described as successful OS input tests.

Hardware Thai input/IME composition, screen-reader behavior and switching the OS's real DPI setting remain unverified. If those fail a product requirement, revisit this choice before building on the affected behavior.

## Scope

This is the CP1 mock-data interface. It does not claim a working Windows network provider or persistent profile store. Core models/validation are separate from the GUI so that subsequent backend work can be tested independently.
